## 一、阻塞（不解决无法开工）

### BLOCK-1 [阻塞] §5.1.3 —— compare() 把一切 exit==1 当作 DIVZERO，唯一性假设未论证

`norm_tavm` 在 `exit_code == 1` 时无条件追加 `"DIVZERO:" + len(lines)`。但 exit 1 的真实语义只是"main 进程异常死亡（reason ≠ nil）"（§1.1 自述）。文档没有回答：
- v0 子集内 main 还有哪些异常死亡原因（例如：穷尽性缺失只是 warning，那运行期 match 无任何臂命中时是返回 nil、panic 还是进程死亡？死亡时 exit 是几？）；
- 这些其他死因的 stdout/stderr/exit 特征是否与除零死亡可区分。

若存在第二种 exit=1 且 stderr 为空的死因，compare() 会把它伪装成 DIVZERO 协议行，metamorphic 主断言出现假对齐（两侧同错）或假 mismatch，失败分类学的 `unexpected-divzero` 类目也随之失真。
另附实测发现：`tinyactor run` 对 **build 失败**也返回 exit 1（已实测），与 main 崩溃的 exit 1 撞车，runner 必须靠 stderr 内容区分，文档未提。

**期望补充**：main 异常死亡的完整原因枚举表（reason 值 × stdout/stderr/exit 特征）；DIVZERO 协议行的判定条件改为"exit==1 且 stderr 匹配除零特征"或等价的可靠判据；以及一条生成器不变式："gen 产出的程序唯一可能的致死路径是除零"（并说明 match 落空行为已被该不变式排除的依据）。

### BLOCK-2 [阻塞] §1.1 / §5.3 —— 运行时 print 的 pair 打印规则描述不完整，golden 逐字节复刻必然出错

§1.1 写"pair=`(a b c)` 空格分隔递归打印"。已核实 `src/vm.c:150-156`（print_val）：当 cdr 链终止于非 nil 值时输出 `" . "` 点对形式（`(cons 1 2)` 实测打印 `(1 . 2)`）。v0 子集明确包含 `cons/car/cdr` 与 `[h, ..t]` 解构，生成的程序完全可能 print 出不规整 pair / 嵌套 dotted 结构；golden 解释器的 print 必须**逐字节**复刻该行为（含点对分支、嵌套规则），按文档现有描述实现出来的渲染器在此类程序上必然 mismatch。
另实测确认：list 字面量 `[1,2,3]` 经 print 输出 `(1 2 3)`——文档也未写明 list 字面量的运行时打印形态，golden 同样依赖它。

**期望补充**：把 print_val 的完整算法（int/float/nil/bool/symbol/string/pair 正规链/dotted 终端/pid/兜底 `?`）写成伪代码或逐分支表格收进 §5.3，作为 golden print 的实现规范；明确生成器是否/如何避免打印 dotted pair，若不避免则 dotted 格式为必测项。

### BLOCK-3 [阻塞] §5.2 Tier B / Tier C —— 高阶变换产物的类型注解规则缺失，且与 spec 直接冲突

T11 的展开形态 `(f a) ↝ ((fn(g){g})(f) a)` 要求把函数值 f 作为实参传递，即 `g` 是函数类型参数。但已核实 spec《支持的注解类型》明确写着"**不支持箭头类型作为注解**"；实测 `fn callf(g: fn(Int)->Int){...}` 直接 type error，甚至文档自己的示例注解风格 `x: Int` 都会 reject（见 CONTRA-1）。只有**无注解参数**（靠推断）能通过（实测 `fn callf(g){ g(41) }` 传入函数可行）。
这意味着：
- gen 的"类型化表达式"模型必须能表达"函数类型参数不得写注解"这一规则，文档只字未提；
- Tier A 骨架里所有参数都带 `: Int` 注解的风格与 Tier B 变换所需形态互相冲突；
- T12 η 展开对**零参**函数（`fn{..}`）的包装写法依赖 `fn(){ body }` 这种显式空参形式是否存在（实测存在，但文档只列了 `fn(x){}` 与 `fn{..}` 两形态）。

不补此规则，Tier B 每个变体都会系统性 reject，整条 λ-结构战线无法启动（Tier C 的 CPS 变换同样大量引入高阶中间函数，同理）。

**期望补充**：gen 类型模型的函数类型表达规则（推荐：函数类型的绑定一律省略注解、由 typecheck 推断，并给出一个实测通过的三行样例）；确认 `fn(){}` 显式空参形式入子集；T12 对 n=0 的展开形态定义。

## 二、矛盾

### CONTRA-1 [矛盾] §5.0 / §5.1.1 —— 示例与骨架使用 `Int` 大写注解，与权威 spec 及实际 typecheck 行为不符

§5.0 子集表、最小完整示例、§5.1.1 骨架全部写作 `fn add(a: Int, b: Int) -> Int`。已核实 spec 写基本类型为小写 `` `int`, `string`, `bool`, `pid` ``，且实测 `fn inc(x: Int)` 报 `cannot unify int -> int with Int -> Int`，直接编译失败。虽然文中有一句"字段拼写以 spec 为准"的免责，但该示例自称"gen 输出形态的**规范样例**"，照抄必败，且会让人误以为大小写无关。
**期望补充**：全文示例统一改为实测通过的形态（`a: int` 等），或明确声明"示例中大写 Int 仅为示意、实际拼写见 spec 类型表"并给出正确版本各一份。

### CONTRA-2 [矛盾] §5.0 vs §5.3 —— 字符串"ASCII 无转义"与仓库事实及本文档自身冲突

§5.0 说字符串字面量"ASCII 无转义"。已核实 `test/basic/string-escapes.ta`：TA 字符串支持 `\n \r \t \\ \" \' \` + `\xNN` 十六进制转义，未知转义原样保留。同时本文档 §5.3 编码表又写 string dump 为"带引号，**转义解码**"，暗示存在转义——同一文档内部两处口径不一。
若 v0 确实想排除转义（作为生成器约束而非语言事实），必须显式写成"语言支持转义（引 test 文件），gen 不产出含反斜杠的字符串字面量"；否则 golden 的字符串读取/print 复刻逻辑无所适从（print 是原样输出解码后的字节，dump 又要重新编码转义，两条规则都要写清）。
**期望补充**：修正 §5.0 表述；在 §5.3 补 string 的 dump 编码规则（哪些字节转义、`\xNN` 是否复现）与 golden print 的对应规则；明确 gen 层的规避约束。

### CONTRA-3 [矛盾] 文档头部 —— 承诺的"文末附注"不存在

头部称评审报告"/tmp/design-review-output.md **存档于本文末尾附注**"，但正文止于 §11 风险表，没有任何附注/附录。/tmp 路径本身也不可靠（重启即失）。
**期望补充**：删掉该句，或真正附上报告并把存档位置改为仓库内持久路径。

### CONTRA-4 [矛盾/歧义] §5.4 —— 锚点断言的伪代码把源码文本喂给了 norm()

`assert compare(norm_golden(B), norm(E₀))`：E₀ 在前文是源码文本（或 gen 树），不是运行结局；compare 的定义域是"两个结局（行列表）"。此处应为 `norm_tavm(out_E0, exit_E0)`。另架构图写 `run.scm：tinyactor build+run`，而 §5.4 伪代码写 `tavm_asan run P`——到底调哪个可执行、如何拿到 asan 构建，前后不一致（详见 MISS-2）。
**期望补充**：修正伪代码；统一并写死 runner 的被调命令。

## 三、歧义

### AMBIG-1 [歧义] §1.1 —— int48 值域写法"±2⁴⁷"

§5.0 钉死的是不对称区间 `[-2⁴⁷, 2⁴⁷)`（w48 代码也如此），±2⁴⁷ 的写法暗示对称。负界可表示、正界不可表示，这对边界值注入是实质差别。
**期望补充**：统一为 `[-2⁴⁷, 2⁴⁷)`。

### AMBIG-2 [歧义] §10 DELIV-2 场景 2/3 —— 用例写成伪记法而非可运行源码

`(2^47-1)+1`、`7/(0-2)`：TA 没有 `^` 运算符（位运算被排除、运算符表中亦无乘方），这些是数学速记。验收场景应当是可以直接粘贴运行的。
**期望补充**：给出真实 TA 源码形式的用例（含按 §5.0 负数规则的书写），如 `print(140737488355327 + 1)`、`print(7 / (0 - 2))`，并注明期望输出。

### AMBIG-3 [歧义] §5.2 T11 —— 第二展开形态中 `e'` 未定义

`e ↝ (fn(x){e'})(e)`：e' 与 x、e 的关系未说明。若意为恒等包装 `(fn(x){x})(e)` 应直说；若 e' 含 x 则这是另一种变换，正确性条件不同。
**期望补充**：明确 e' 的定义（推测为 x 本身），删除或解释第二形态。

### AMBIG-4 [歧义] §9 —— "滚动新 seed"的推导规则未定义

快速环"固定 seed 基准集 + 滚动新 seed"：新 seed 从何而来（日期？git sha？计数器？）？"同 seed 同程序"的去重与失败复现承诺是否覆盖滚动部分？
**期望补充**：seed 派生公式 + 失败报告中记录 seed 的要求（§5.4 已有落盘契约，补上派生规则即可闭环）。

### AMBIG-5 [歧义] §10 DELIV-1 —— "test/compiler/ 中合法程序"的判定标准

合法 = 非 `*-errors*`/`*-parse-errors*` 文件名？还是逐一试 dump？文件名启发式漏判/误判时以什么为准？
**期望补充**：一句话钉死（建议：文件名排除 + dump 失败即列入 expected-fail 清单人工复核一次，此后清单固化）。

### AMBIG-6 [歧义] §4 / §5.4 —— 变换操作的对象是树还是渲染后的源文本

DEC-3 说 gen"在自己的树结构上做变换，输出时全括号化"；§5.4 却写 `Eₖ ← apply(t, E₀)`，而 E₀ 已是"强制多行排版"的程序。变换库操作 gen 树、渲染发生在何时、`t.target_node` 指向哪棵树——影响 transforms.scm 的整个接口设计。
**期望补充**：明确管线为 `tree₀ = gen(seed)` → `treeₖ = apply(t, tree₀)` → `srcₖ = render(treeₖ)` → run(srcₖ)，并说明 E₀/Eₖ 记号各指什么。

### AMBIG-7 [歧义] §10 DELIV-3.5 —— "η 展开叠加"与"恰 1 条变换、不叠加"冲突

验收场景 5 写"T12 **叠加**深尾递归探测"，§5.4 铁律是每变体恰 1 条变换。是指"在深递归程序形态上施加 η"还是允许特例叠加？Tier C 也是全程序复合变换，界限在哪。
**期望补充**：为该验收项单独注明豁免或改写为"对深尾递归基准程序施加 T12 后两侧栈有界"。

### AMBIG-8 [歧义] §10 DELIV-2 —— "白名单节点 tag"的机械判定方式

筛选条件"AST 仅含白名单节点 tag"：dump 产出是 s-expr 文本，tag 如何提取（顶层 head symbol？递归所有子节点的 head？`(define ...)`/`('begin ...)` 引号符号怎么算）？
**期望补充**：定义 tag 提取算法（建议：全树遍历，取每个 list 节点的 car 若为 symbol 则收集，与冻结节点表求差）。

## 四、缺失（实现时必然要问）

### MISS-1 [缺失] §4 目录布局 / §10 —— ast-dump.ta 的输入输出契约

`tinyactor run tools/kernfuzz/ast-dump.ta test/basic/closure.ta` 隐含 TA 程序能取 argv、能读任意文件。可行性我已核实（`tinyactor run` 支持附加参数、`vm_set_argv` 存在、`lib/fs.ta` 提供文件读取），但文档没有回答：TA 侧取 argv 的内置函数叫什么、第几个参数是目标路径、用 fs.ta 的哪个函数读文件、输出到 stdout 还是文件。
**期望补充**：ast-dump.ta 的接口签名（argv 约定、读文件 API、输出流）。

### MISS-2 [缺失] §4 / §5.4 —— runner 的确切命令行与 asan 构建获取方式

被调命令到底是 `tinyactor run P` 还是直接 `tavm_asan P.tabc`？asan 构建如何产出（Makefile 目标/环境变量）？wrapper 是否透传子进程 exit code（实测透传，但文档应写明，因为它决定 §5.1.2 表格对 wrapper 同样成立）？超时 kill 后 exit code 如何归类（§5.1.2 只写"被 runner kill"）？
**期望补充**：一张"runner 调用卡"：构建命令、运行命令、超时机制、exit/stdout/stderr 三元组的采集方式。

### MISS-3 [缺失] §5.0 / §5.2 —— gen 的终止性保证未声明

T6（let 内联）、T10（β 归约）、T11（β 展开）在严格求值下的正确性都以"被移动/复制的表达式求值必终止"为前提：若 e 可发散，内联后求值次数改变（零次 vs 一次）会破坏等价（原程序发散、变体终止，或反之触发超时假 finding）。文档从未声明"gen 只产出必终止程序"。
**期望补充**：把终止性写成 gen 的硬不变式（如：递归必须有结构性递减、禁止自引用 let 值），并在 §5.2 各变换的正确性条件里显式引用它。

### MISS-4 [缺失] §5.0 —— 字面量本身的词法回绕规则

边界值集合含 `-2⁴⁷` 及"±小扰动"，但没人说明**字面量本身超出 int48 时会发生什么**：`val_int()` 对超范围字面量截断低 48 位再符号扩展，即源码里的 `140737488355328`（=2⁴⁷）经 parser 后已是 `-2⁴⁷`。gen 若直接输出越界字面量，意图值与实际值静默错位；T4 常量折叠也要决定按"词法回绕后的值"还是"源码字面量"折叠。dump 出的 AST int 节点是否可能出现负值/越界值，直接影响 golden 读取。
**期望补充**：gen 硬规则"字面量绝对值 ≤ 2⁴⁷-1"；T4 折叠以 AST 内已回绕值为准的声明；边界值 -2⁴⁷ 的合法书写形式（如 `(0 - 140737488355328)` 的实际语义说明）。

### MISS-5 [缺失] §5.0 / §6.2 —— ADT 声明的语法示例与 spec 章节指针

子集表 ADT+match 行打了 ✅，但没有声明语法示例（`type T = ...`？），spec 章节指针也只给了"match 表达式"。L2 负例第 4 类"构造器字段类型错配"、gen 产出 ADT 构造/match 构造器模式，都需要它。spec 有《ADT（代数数据类型）·声明语法》章（已核实存在），补个指针即可，但现在是空白。
**期望补充**：一行声明语法示例 + spec 章节指针 + 构造器在 match 模式中的写法。

### MISS-6 [缺失] §7.3 —— 多重集 harness 所需的 actor API 细节无指针

collector"收满 K*M 条后……然后 HALT"：TA 如何让一个 actor 结束（有无 halt/正常返回即死的语义）？spawn/send/receive 的确切签名、消息负载类型、pid 类型注解写法、`"<wid> <seq>"` 行的字符串拼装用什么（str.concat/str.from_int？）——§5.0 排除了 actor 且 §7.3 未像 §5.0 那样给 spec 指针（spec 有《Actor 模型》章，已核实）。
**期望补充**：§7.3 开头加 actor 构造的语法指针表（对齐 §5.0 风格），并明确 collector 终止机制与消息编码格式。

### MISS-7 [缺失] §5.4 / §4 —— 落盘路径与固化产物位置

`findings/<类别>-<hash>/` 有了，但：AST 快照（`*.sexp`）放哪、重建命令是什么；fast 环"typecheck 固定 seed 负例回归集（固化快照）"存哪、格式为何、如何再生成。目录布局图里都没有。
**期望补充**：目录布局补 `snapshots/`、`corpus/`（或同类）及各自再生成 make 目标。

### MISS-8 [缺失] §5.4 —— applicable_transforms 不足 3 条时的行为

DELIV-3.1 验收要求"每程序恰 3 变体"，但某些 E₀（如近乎纯字面量的程序）可用变换可能少于 3。跳过程序会破坏"恰 3"统计，重采样又与确定性 seed 冲突。
**期望补充**：定义 fallback（建议：不足时重 roll 子 seed 直到满足或设上限后记 skip，skip 不计入验收分母）。

### MISS-9 [缺失] §6.3 / DELIV-9 —— fmt 幂等性的操作契约

fmt 工具实际存在（`tinyactor fmt <file>.ta` **就地**改写、`--check` 模式，已核实），但文档没写幂等性检查的工作流：就地改写意味着必须先复制 P→P.fmt、fmt 副本、分别编译、比较两个 `.tabc`；临时文件放哪、`.tabc` 输出路径约定（`build` 支持指定 out，已核实）。另外 `.tabc` 全文仅一处出现、未定义（可推断为字节码产物，但应点名）。fast/nightly 各环覆盖哪些 Tier（B/C 进不进 nightly）也没写。
**期望补充**：fmt 幂等性检查的分步命令序列 + 各 CI 环的 Tier 覆盖矩阵。

### MISS-10 [缺失] §5.2 T8 —— 不重叠标记的实现载体

"仅当生成器标记两两不重叠"：标记存在 gen 树的哪里、transform 如何查询（arm 上的元数据字段？模式形状的静态可判定函数如"通配臂仅末位"？）。
**期望补充**：标记的表示与判定规则（哪怕就是一句"通配臂存在 ⇒ 仅允许交换非相邻通配前的两两不相交臂"的可执行谓词）。

### MISS-11 [缺失] §5.0 —— 作用域规则未钉死，golden 环境模型必需

let 的作用域（绑定在其后整个块可见？能否自引用？）、顶层定义是否全体相互可见（互递归允许与否）——遮蔽链探测和 golden 的环境链实现都建立在这之上，§5.0"语义钉死项"漏了这条。
**期望补充**：作用域三条（let 绑定可见范围、顶层可见性、互递归裁决）+ 各配一行 spec 指针。

### MISS-12 [缺失] §6.2 —— 负例变异的"保解析性"约束

四类 reject 型变异如果意外制造了 **parse error** 而非 type error，"stderr 含 typecheck 关键词"断言会误报 finding（parse 错误文案不同）。需要规定：变异构造必须保持可解析（先本地验证 parse 通过才入库），或把 parse-reject 设为独立类别不计入 reject 断言。
**期望补充**：一条变异前置校验规则 + parse-reject 的归类裁决。

### MISS-13 [缺失] §5.4 / §5.3 —— golden/main.scm 的输入输出契约与调用方

读 stdin 还是 argv 文件路径？输出到 stdout 由 run.scm 捕获？guile 命令行（`guile --no-auto-compile -s main.scm < in.sexp`？）。compare 双方都要消费它的 stdout，接口必须冻结。
**期望补充**：main.scm 的 argv/stdin 约定与一行示例调用。

## 五、存疑（已完成仓库核实，附结论）

### SUSP-1 [存疑→已证伪] §5.0 字符串"无转义"
仓库存在 `test/basic/string-escapes.ta`，TA 支持 `\n\r\t\\\"\'\xNN` 转义。见 CONTRA-2。

### SUSP-2 [存疑→已证伪] §5.0 示例 `Int` 注解
实测 `fn inc(x: Int) -> Int` 被 typecheck reject；spec 权威为小写 `int`。见 CONTRA-1。

### SUSP-3 [存疑→已证实] §1.1 pair 打印"空格分隔递归"
描述不完整：`vm.c:150-156` 存在 dotted 分支，实测 `(cons 1 2)` 打印 `(1 . 2)`。见 BLOCK-2。

### SUSP-4 [存疑→已解除] §7.4 TSan 构建是否存在
存在：`TSAN=1 make tavm`（Makefile:24-35）。建议文档补一句构建命令（并入 MISS-2 的调用卡）。

### SUSP-5 [存疑→已解除] ast-dump.ta 可行性（argv/文件读取）
`tinyactor run <src> [args...]` 支持透传、`vm_set_argv`（api.c:663）、`lib/fs.ta` 在。可行性成立，接口契约仍缺（MISS-1）。

### SUSP-6 [存疑→已核实相符] §1.1 运行时事实引用
`tavm.c:136-141` exit 语义、`fflush+fsync`、`val.c` int48 截断/符号扩展、`driver.ta:364-368` 的 `typecheck: N type error(s) found` 行、parser.ta use 位负号折叠、`fn(){}` 显式空参形式、list 字面量打印 `(1 2 3)`——均与仓库一致。

### SUSP-7 [存疑→建议] §5.4 fnv128
FNV 家族常规是 32/64 位，128 位变体罕见且各实现参数不一。建议指明参考实现或改用 SHA-256 截断，避免"签名"跨机器不可复现。

### SUSP-8 [存疑→低优] §1.1 "算术走 C int64 再截断……等价于干净模运算"
模 2⁶⁴ 后再模 2⁴⁸ 与直接模 2⁴⁸ 同余，数学上成立；但 C 有符号溢出是 UB，编译器理论上可利用。golden 用大整数+w48 是对的，此条不影响实现，仅提示 VM 侧断言依赖 -fwrapv 类保证与否值得在 DELIV-7 里写一句。
