## 壹 [阻塞] —— 无法开工的信息缺口

**B1. [阻塞] §5.3 / §3-D2 — AST s-expr 编码约定不完整，两个工具链组件无法对接。**
文档只给了 4 条：pair→`(...)`、symbol→原样、string→带引号转义、int→十进制。缺：AST 节点的 tag 形态（是 `(binop + a b)` 这种带标签 list 吗？）、nil/空表如何打印、bool 打印成什么、string 转义的具体规则（无转义子集下还需要转义吗）、嵌套 quote 的表示。
期望补充：一份完整的 dump 文法（EBNF 或示例对照表：TA 构造 → 确切 s-expr 文本）。

**B2. [阻塞] §5.3 — AST 节点形状"以 `test/compiler/parser-ast.ta` 为准（实现第一步核对并冻结）"是将规格外包给逆向工程。**
interp.scm 要对每个节点的字段顺序做模式匹配，不知道节点清单就一行 eval 都写不了；ast-dump.ta 同理。
期望补充：文档内嵌节点清单（每种语法构造的 tag + 字段顺序 + 示例），parser-ast.ta 仅作为权威佐证引用。

**B3. [阻塞] §5.2 T7 — "尾递归函数 ↔ 等价 while 循环改写"的目标形态在语言中不存在。**
§5.0 子集定义里没有任何循环构造；（已核实）parser 中无 `while`/`loop`/`for` 关键字。T7 无法实现，且它是 8 条首发变换之一、自检场景还拿 T3 之外的它当参照（D2 否决 Go 的理由也挂在它上面）。
期望补充：要么从 v0 变换集中删除 T7 并补一条替代变换，要么明确 v1 才引入循环构造并同步修订 §5.0、D2 论证、验收场景。

**B4. [阻塞] §5.0/§5.1 — TA 语言语法零引用，gen.scm 生成合法源码无从下手。**
文档只在骨架里出现 `fn helper_1(a: Int, b: Int) -> Int { ... }` 和 T6 的 `let x=e in body`（花括号块语言里冒出 `in` 关键字记法，两者是否同一语法不明）。fn 定义/递归具名函数的绑定语法、ADT 定义语法、match 臂语法、list 模式 `[h, ..t]` 的确切拼写全部缺失。仓库明明有 `docs/ta-language-spec.md` 但文档从未指向它。
期望补充：§5.0 子集每一构造附语法产生式（或至少给出权威 spec 的章节引用），并给出一个完整可编译的最小示例程序。

**B5. [阻塞] §5.0/§5.3/§5.4 — divzero 比对协议只定义了 Scheme 一侧。**
Scheme 侧输出 `DIVZERO:<已打印行数>`；但 tavm 侧（已核实 vm.c:295-298：整除除零只是杀掉当前进程并投递 DOWN 消息，不打印任何协议行）：① 顶层 main 进程 divzero 死亡时 stdout/exit code 的表现是什么？② `DIVZERO:<n>` 这一行由谁产出——tavm、runner 归一化、还是要求被测程序自己捕获 DOWN 并打印？③ "已打印行数前缀"由谁统计、stdout 在进程死亡时是否保证 flush？
期望补充：一段明确的端到端协议：tavm 死亡时的可观测信号（exit code/stderr）→ runner 归一化规则 → 与 golden 的 `DIVZERO:<n>` 行如何对齐。

**B6. [阻塞] §6.1 — typecheck 的调用接口未定义。**
A1 断言"typecheck 必须 accept（exit 0）"：typecheck 是 `tinyactor build` 的副作用还是有独立入口？诊断走 stdout 还是 stderr？exit code 语义（0=接受？非 0=拒绝？有无 panic 专用码）？没有这些，双向 oracle 的断言代码写不出来。
期望补充：typecheck 触发命令、三种结局（accept/reject/crash）各自的可观测特征。

**B7. [阻塞] §7.3 — 多重集 harness 只有两条注释级描述，无法实现。`
K=16,M=100` 骨架无实体：driver 是什么（Guile 编排？bash？TA 写的 driver 程序？）、worker/collector 骨架的完整 TA 源码模板、payload 如何选取、超时阈值多少、"排序摘要"的确切打印格式、与预期枚举比对的实现位置与语言。
期望补充：完整的 harness 骨架源码或伪代码 + 运行命令 + 判定逻辑。

**B8. [阻塞] §10 P0-D3-4 — reduce.sh 的验收硬指标"≤15 行且仍复现"没有任何达成依据。**
生成物是全括号源码，可能压成单行长表达式，此时"行删除"一步都删不动；token 删除阶段必须维持"同一失败签名复现"，而签名含源码哈希（§5.4），归约后的源码哈希必然改变——去重签名与归约判据如何兼容未说明；15 这个数字从何而来也无论证。
期望补充：归约的复现判据定义（是签名匹配还是类别匹配而非全哈希匹配）、生成器输出强制多行排版、以及 ≤15 行指标的推导或降级为"尽力而为"。

## 贰 [歧义] —— 两种以上合理解读

**A1. [歧义] §5.0 — "匿名闭包 `fn(x){..}` 与 `fn{..}`"。**
`fn{..}` 是零参闭包语法、多参省略括号语法，还是笔误？两种形式在 AST 里是否同构？
期望补充：两种形式各自的语法地位与 AST 表示。

**A2. [歧义] §5.0 排除项 — "const（除非 gen 需要哨兵值）"。**
哨兵值指什么？为什么 const 会影响 gen 取哨兵？这条例外何时生效？
期望补充：具体场景说明，否则删除该括号。

**A3. [歧义] §5.2 T8 — "单构造器穷尽 match ↔ 直接解构"。**
"直接解构"是什么语法？TA 有解构 let / 模式绑定语句吗（§5.0 子集未列）？右侧形态若不在子集内，该变换产出的程序可能根本不能编译。
期望补充：右侧目标形态的语法及其在子集中的合法性证明。

**A4. [歧义] §5.4 — `V ← [E₀] ++ [apply_random_transform(E₀) for k in 1..3]`。**
每个变体恰好施加 1 条变换（共 3 个独立变体），还是变换叠加累积（E₀→Tᵢ→Tⱼ→…）？变换可否组合？随机选择是均匀分布还是加权？报告里的"变换路径"记录格式？
期望补充：伪代码级别的变换应用策略 + 变换路径的数据结构定义。

**A5. [歧义] §5.0 vs §5.4 — 除零时两条比对协议不一致。**
§5.0 说按"(退出原因, 已打印行数前缀)"匹配；§5.4 主断言说"out 逐行字节比对 且 exit 一致"。divzero 场景下前缀匹配 ≠ 字节全等（若一侧多打了一行才死）。以哪条为准？
期望补充：统一为一个比对函数的定义，明确 divzero 是特例分支还是统一协议。

**A6. [歧义] §5.4 — 签名去重 `失败类别 ∪ fnv128(strip_ws(源码))`。**
`∪` 是字符串拼接还是集合操作？签名的最终形态是二元组 (类别, hash) 吗？"失败类别"的枚举清单（crash / mismatch / timeout / unexpected-divzero / …）从未给出。另外 P0-D3-3 说"同一失败 seed 重跑被跳过"，这隐含 gen 必须对 seed 确定性，但全文未声明该前提。
期望补充：签名的精确定义、失败类别分类学、gen 确定性要求显式化。

**A7. [歧义] §7.2 — gc/workloads.scm 的服务对象不明。**
workloads 包含 spawn/death/消息 churn 等并发形态，但 §7.2 顺序差分明确限定"单 actor 确定性程序"。这些 workloads 到底喂给 stress-vs-normal 差分、多重集 harness、还是 TSan 长跑？三者皆喂的话，含 send 的负载进 stress 差分就突破了"单 actor"限定。
期望补充：workload 分类 × oracle 的映射矩阵。

**A8. [歧义] §10 P0-D1-2 — "人为改动 parser.ta 任一节点结构后重跑 → 快照 diff 非空"。**
这是一次性手工验收步骤，还是要固化为常驻自动化测试？后者的话"人为改动"在 CI 里如何表达（fixture 化的恶意 parser 分支？）？另外并非"任一"内部改动都会反映到 dump 输出（如改内部字段名不改打印），"必须非空"作为硬断言过强。
期望补充：验收性质（一次性 demo 还是 CI 用例）与可自动化的执行方式。

**A9. [歧义] §9 — 快速环"typecheck 负例回归"。**
§6.2 的负例是随机生成的，"回归"一词意味着固定集合。快速环用固定 seed 固定负例集，还是每次现生成？它与 nightly 2000 例的关系（子集？抽样？）。
期望补充：快速环负例集的来源与固化方式。

**A10. [歧义] §3 vs §8 vs §10 — 两套 "D" 编号体系并存。**
§3 设计决策编号 D1–D6，§8 交付物编号 D1–D10，§10 验收场景又用 "P0-D3/P0-D5"（指交付物）。"D5" 在 §3 是决策五、在 §8/§10 是 typecheck oracle，极易混淆。
期望补充：决策改名（如 DEC-1）或交付物改名（如 DELIV-1）。

**A11. [歧义] §5.2 T4 — 常量折叠结果的源文本表示。**
折叠可能产出 -2⁴⁷ 这类负数，写回全括号源文本时负数如何表示（一元减？负字面量？）与词法层 `-` 解析交互未说明；若 `-2⁴⁷` 被解析为 `(- 0 2⁴⁷)` 则 T4 的"折叠值"本身又是一个表达式。
期望补充：负数折叠值的规范化写出规则。

**A12. [歧义] §5.2 T7 — "-max-stack 类观测，若无则仅比结果"。**
已核实 CLI 无任何 stack 选项，该兜底永远走"仅比结果"分支，含糊表述应删除。且 TA VM 已有 OP_TAIL_CALL（TCO 存在），T7 的"正确性条件"到底检验什么（栈深有界如何在不观测栈的情况下验证？）没有可操作定义。

**A13. [歧义] §6.3 — "结论翻转数 = 0"中"翻转"的粒度。**
指 accept↔reject 结局翻转，还是包括诊断条数/内容变化？"确定性"性质要求诊断逐字节一致，而"顺序无关性"只要求结论不变——两者粒度不同是有意为之还是疏漏？

## 叁 [缺失] —— 实现时必然要问的问题

**M1. [缺失] §5.1 — print 的输出格式协议。**
Int 打印（十进制？负号？有无前后缀）、bool/string 打印格式、print 是否自带换行、行尾是 `\n` 还是平台换行——全部 oracle 都建立在"stdout 逐行字节比对"上，行格式却从未定义。
期望补充：print 各类型值的精确输出规范（含示例）。

**M2. [缺失] — exit code 协议。**
tavm 正常结束、main 进程 divzero 死亡、panic、超时被杀各自的退出码与 stderr 特征。runner 判定"exit 一致"（§5.4）必须有这张表。

**M3. [缺失] §5.3 — golden 的输出流定义。**
main.scm"读 sexp → 求值 main → 打印结果流"：main 无返回值时结果流是否只含 print 行？若 main 有返回值，打印格式与 tavm 侧行为如何对齐？

**M4. [缺失] §5.0 — match/ADT 语义钉死清单缺失。**
臂匹配顺序（首匹配？）、重叠模式的语义、跨 ADT 同名构造器的解析规则、guard（语料里有 guard-arm 测试，说明语言有 guard）是否入 v0 子集——golden 实现 match 必需，文档一字未提。
期望补充：match 求值规则的精确规范并入"语义钉死项"。

**M5. [缺失] — 闭包捕获语义。**
捕获按值快照还是按共享引用？被捕获变量后续被赋值（语言可变吗？）时闭包看到什么？语料中的 closure-overwrite-scope.ta 暗示这里有微妙历史 bug，T6 的 alpha 换名和 golden 的环境模型都依赖此语义，文档未写。
期望补充：捕获模型的规范陈述（哪怕一句话 + 一个判别性示例）。

**M6. [缺失] — 负数字面量与一元减在 AST 中的表示。**
`-2` 是字面量节点还是一元 neg 应用？直接影响 ast-dump 编码、gen 的负数注入（边界值含 -2⁴⁷）与 golden 的求值。

**M7. [缺失] §5.4 — tavm_asan 的构建与定位约定。**
构建命令（make 目标名）、产物路径、runner 在 CI 与本地分别如何找到它。

**M8. [缺失] §5.4 — finding 落盘的内容契约。**
`findings/<sig>/` 里除源码、seed、变换路径外还应有什么（E₀ 与各变体的 stdout/stderr/exit code、golden 输出、ASan 报告）？"失败类别"分类学与目录组织（同类多 finding 共目录？）未定义。

**M9. [缺失] §5.4 — morph runner 超时的归类。**
5s 超时算 finding 还是 skip？§7.3 对并发 harness 明确超时=finding，morph 未说（而 hang 恰是该 fuzz 线的历史主要战果，不应留白）。

**M10. [缺失] — "语料库"的范围定义。**
"对语料库全部 `.ta` 生成快照"（P0-D1-2）：包含 `*-errors.ta`/`*-parse-errors.ta`（本就不合法，dump 应失败，成功反而异常）吗？test/compiler、test/actor、example/ 算吗？P0-D2-1 "属于 §5.0 子集的程序"的筛选是人工维护的白名单还是自动探测？期望补充：语料库目录清单 + 子集筛选机制。

**M11. [缺失] §4/§8-D10 — Makefile.inc 的对外接口。**
`make kernfuzz-fast / kernfuzz-nightly` 的参数传递方式（seed、batch 数量如何覆盖）、Guile 版本下限（R7RS 支持程度因版本差异大）、检测失败时的退出语义（§11 说了警告降级，但 fast 目标自身的 exit code 是 0 还是非 0——CI 判定需要知道）。

**M12. [缺失] §5.3 — w48 的适用位置约束。**
w48 公式本身正确，但未声明关键实现约束：golden 内部全程使用 Scheme 任意精度整数、仅在每次算术后 w48 归一。不写明，实现者很可能用 fixnum/int64 中间量造成双重截断。一句话即可，但必须有。

**M13. [缺失] §6.1 A3 — gen 记录"预期值"的机制。**
gen 要对自己生成的含闭包程序预言运行结果，等于内置半个求值器（与 golden 职责重叠）；还是只对纯常量子表达式记录预期？"抽查 10%"抽哪些？
期望补充：预期值的产生机制与抽查抽样规则。

**C5. [矛盾] §5.2 T7 vs §5.0 — 首发变换依赖子集中不存在的循环构造**（详见 B3，既是阻塞也是子集定义的自相矛盾）。
